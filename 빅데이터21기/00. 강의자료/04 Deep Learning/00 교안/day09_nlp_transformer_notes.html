0. 왜 RNN이 아니라 Transformer인가

많은 교재가 NLP를 RNN → LSTM → Transformer 순서로 가르친다. 개념 설명에는 좋은 순서지만, 2018년 이후 실무에서 텍스트 분류·번역·생성에 RNN 계열을 새로 쓰는 경우는 거의 없다. 이 노트는 처음부터 Transformer 기준으로 전체를 다시 구성했다.

같은 문제를 푸는 두 구조의 차이
기준RNN · LSTMTransformer
입력 처리단어를 한 개씩 순차적으로문장 전체를 한 번에
병렬화불가능 (이전 결과를 기다려야 함)완전 병렬 — GPU 효율이 높다
먼 단어 연결거리가 멀수록 신호가 희미해짐거리와 무관하게 한 번에 연결
순서 정보구조 자체에 내재위치 인코딩으로 따로 주입해야 함

RNN이 완전히 죽은 것은 아니다

입력이 끝없이 들어오는 스트리밍 처리, 메모리가 극히 제한된 온디바이스 환경, 짧은 시계열 예측에서는 O(n)인 순환 구조가 여전히 유리하다. 최근 Mamba 같은 상태공간 모델(SSM)이 '순환 구조의 귀환'으로 주목받는 것도 이 때문이다. 다만 일반적인 텍스트 이해·생성 과제의 기본값은 Transformer다.

1. 자연어 처리란 무엇인가

사람은 "오늘 기분이 좋아요"를 읽는 순간 긍정적인 감정을 알아챈다. 컴퓨터에게 이 문장은 기호와 문자의 나열일 뿐이다. 이 간극을 메우는 기술이 자연어 처리(Natural Language Processing, NLP)다.

좁은 의미
텍스트를 컴퓨터가 계산할 수 있는 숫자 형태로 변환하는 과정.
넓은 의미
인간의 언어를 이해·생성하는 인공지능의 한 분야. 변환된 숫자로 감정을 분석하고, 번역하고, 요약하고, 대화하는 일 전체.

어디에 쓰이나

기계 번역(Google 번역기, Papago), 대화형 AI(ChatGPT, Claude), SNS 감정 분석, 검색과 추천, 문서 요약, 코드 생성. 오늘날 이 목록의 거의 전부가 Transformer 위에서 돌아간다.

왜 어려운가

  • 모호성(Ambiguity) — "배가 아프다"의 배는 신체, "배를 타고 떠나다"의 배는 교통수단이다. 같은 철자, 다른 의미.
  • 지시 대상 파악 — "민수는 [중략] 그래서 그는 매우 슬펐다"에서 '그는'이 민수임을 알아야 한다.
  • 언어의 불규칙성 — 문법 규칙과 예외가 많고 언어마다 구조가 다르다.
  • 데이터 부족과 편향 — 저자원 언어는 학습 데이터 자체가 적고, 있는 데이터도 한쪽으로 치우쳐 있다.
  • 긴 문맥 — 의미를 이해하려면 수천 단어 전의 내용까지 붙들고 있어야 한다.

Transformer는 이 중 모호성과 지시 대상 문제를 셀프 어텐션으로, 데이터 부족 문제를 사전학습·전이학습으로 크게 완화했다. 긴 문맥과 편향은 여전히 활발한 연구 주제다.

기술의 계보

문법 규칙 기반 → 확률·통계 기반(n-gram) → 신경망 기반(RNN, LSTM) → Transformer(2017, "Attention Is All You Need") → 사전학습 언어 모델(BERT 2018, GPT 시리즈) → 대규모 언어 모델(LLM).

왜 서브워드인가

단어 단위 토큰화에는 두 가지 고질적인 문제가 있었다.

  • OOV(Out-Of-Vocabulary) — 사전에 없는 단어는 전부 <UNK>가 되어 정보가 통째로 사라진다.
  • 사전 폭발 — 한국어처럼 조사·어미가 붙는 언어는 어휘 집합이 수십만 개로 커진다.

서브워드 토큰화는 자주 등장하는 조각은 통째로, 드문 단어는 조각으로 쪼개서 이 둘을 동시에 해결한다.

"unhappiness"  →  ["un", "happi", "ness"]
"토큰화하겠습니다" →  ["▁토큰", "화", "하겠", "습니다"]
"ㅋㅋㅋㅋ루삥뽕"   →  ["ㅋㅋ", "ㅋㅋ", "루", "삥", "뽕"]   ← 신조어도 UNK가 되지 않는다
알고리즘원리대표 모델
BPE Byte Pair Encoding가장 자주 붙어 나오는 문자 쌍을 반복해서 병합GPT 계열, RoBERTa
WordPiece병합했을 때 말뭉치 확률이 가장 크게 오르는 쌍을 선택BERT
SentencePiece Unigram공백까지 문자로 취급해 언어 구분 없이 학습T5, LLaMA, 한국어 모델 다수
한국어 형태소 분석은 이제 필수가 아니다

RNN 시절에는 KoNLPy나 Kiwi 같은 형태소 분석기로 "먹었습니다"를 ["먹다","었","습니다"]로 쪼개는 전처리가 필수였다. 지금은 SentencePiece 계열 토크나이저가 통계적으로 비슷한 분할을 학습으로 찾아낸다. 형태소 분석기는 검색 색인, 키워드 추출, 언어학적 분석처럼 사람이 결과를 읽어야 하는 작업에서 여전히 유용하다.

3. 임베딩과 위치 정보

임베딩의 출발점: 분포 가설

언어학자 젤리그 해리스(Zellig Harris)가 1954년에 남긴 관점 — 비슷한 맥락에서 쓰이는 단어들은 비슷한 의미를 가진다. 이를 분포 가설(Distributional Hypothesis)이라 하며, 오늘날 단어 임베딩의 핵심 철학이다. '강아지'가 나오는 문장에는 '귀엽다', '산책', '주인'이 함께 등장한다.

벡터(Vector)란

여러 숫자를 모아 하나의 의미를 표현하는 단위다. 어떤 사람을 [175cm, 70kg, 25세]로 나타내는 것처럼. 단어를 벡터로 바꾸면 컴퓨터가 단어의 유사도와 관계를 수학적으로 계산할 수 있다.

임베딩의 발전 3단계

단계대표원리한계
빈도 기반BOW, TF-IDF단어가 몇 번 나왔는지 센다의미 유사성·순서·문맥을 못 담음
정적 임베딩Word2Vec, GloVe주변 단어와 함께 등장하는 패턴을 학습단어 하나에 벡터 하나 — '배'가 문맥에 따라 달라지는 것을 표현 못함
문맥 임베딩BERT, GPT문장 전체를 보고 같은 단어라도 매번 다른 벡터를 만듦연산 비용이 큼

Transformer의 결정적 성과가 세 번째다. "배가 아프다"의 '배'와 "배를 타고"의 '배'는 서로 다른 벡터가 된다. 모호성 문제가 구조적으로 풀린 지점이다.

위치 인코딩 Positional Encoding

Transformer는 문장을 한꺼번에 보기 때문에, 그 자체로는 단어의 순서를 전혀 모른다. "The dog chased the cat"과 "The cat chased the dog"이 똑같이 보인다. 그래서 위치 정보를 벡터에 더해서 주입한다.

PE(pos, 2i) = sin( pos / 10000^(2i/d) ) PE(pos, 2i+1) = cos( pos / 10000^(2i/d) ) 원논문의 사인·코사인 방식. 위치마다 고유한 파형 패턴을 만들어 임베딩 벡터에 더한다. 학습이 필요 없고, 학습 때 본 적 없는 길이에도 대응된다.
  • 학습형 위치 임베딩 — 위치도 하나의 임베딩 테이블로 학습 (BERT 방식).
  • RoPE(Rotary Position Embedding) — 벡터를 위치에 따라 회전시켜 상대적 거리를 표현. LLaMA를 비롯한 최신 LLM의 사실상 표준.

4. 셀프 어텐션: Transformer의 심장

직관

"그 동물은 너무 지쳐서 그것은 길을 건너지 못했다"에서 '그것'이 무엇인지 알려면 앞의 '동물'을 봐야 한다. 셀프 어텐션은 문장 안의 모든 단어가 모든 단어를 한 번에 둘러보고, 자기와 관련 깊은 단어에 가중치를 몰아주는 연산이다. RNN처럼 정보를 릴레이로 전달하지 않기 때문에, 몇 단어 떨어져 있든 연결 거리는 항상 1이다.

Query · Key · Value

각 토큰 벡터에 서로 다른 가중치 행렬을 곱해 세 가지 역할의 벡터를 만든다. 도서관에 비유하면 이렇다.

  • Query(Q) — 내가 찾는 것. "나는 어떤 단어와 관련이 있지?"
  • Key(K) — 각 단어가 내건 색인표. "나는 이런 단어야."
  • Value(V) — 실제로 가져올 내용물.

Q와 모든 K를 비교해 관련도 점수를 매기고, 그 점수로 V를 가중 평균한다.

Attention(Q, K, V) = softmax( Q·Kᵀ / √d_k ) · V ① Q·Kᵀ로 모든 단어 쌍의 유사도를 구하고 ② √d_k로 나눠 값이 커지는 것을 막고 ③ softmax로 합이 1인 가중치로 바꾼 뒤 ④ V에 곱해 섞는다.

√d_k로 나누는 이유 (Scaled)

차원 d_k가 커질수록 내적값의 분산이 커진다. 그대로 softmax에 넣으면 한 곳만 1에 가깝고 나머지는 0이 되어 기울기가 거의 흐르지 않는다. √d_k로 나눠 분산을 일정하게 맞춰 준다. RNN에서 tanh가 값 폭주를 막던 역할과 목적이 비슷하다.

멀티 헤드 어텐션 Multi-Head Attention

어텐션을 한 번만 하면 관점이 하나뿐이다. 그래서 벡터를 여러 갈래(head)로 쪼개 각각 독립적으로 어텐션을 수행한 뒤 다시 이어 붙인다. 어떤 헤드는 문법적 의존 관계를, 어떤 헤드는 지시 대상을, 어떤 헤드는 바로 옆 단어를 보는 식으로 역할이 자연스럽게 분화된다.

보통 d_model = 512, heads = 8이면 헤드마다 64차원을 담당한다. 총 연산량은 단일 헤드와 같으면서 관점만 늘어나는 것이 핵심이다.

마스킹 두 종류

마스크목적쓰이는 곳
패딩 마스크PAD 토큰을 어텐션 계산에서 제외모든 모델
인과 마스크 Causal미래 토큰을 못 보게 가림 — 다음 단어 예측 학습에 필수GPT 계열 디코더

계산 비용이라는 대가

모든 단어가 모든 단어를 보므로 어텐션 행렬 크기는 n × n이다. 문장 길이가 2배가 되면 연산은 4배가 된다. 이 O(n²)이 긴 문서 처리의 병목이며, FlashAttention(메모리 최적화), 슬라이딩 윈도우 어텐션, 선형 어텐션 등이 이를 완화하려는 시도다.

                                        │
 ├─→ LayerNorm → 피드포워드(FFN) ───────┐
 └──────────────── 잔차 연결 ──────────→(+)
출력  (이 블록을 N번 쌓는다)
피드포워드 네트워크 FFN

각 토큰 벡터의 값 분포를 정규화해 학습을 안정시킨다. 최근에는 블록 앞쪽에 두는 Pre-LN 방식이 표준이다.

사전학습과 파인튜닝

Transformer의 진짜 위력은 구조보다 학습 전략에서 나온다.

  1. 사전학습(Pre-training) — 레이블 없는 대규모 말뭉치로 언어 자체를 익힌다. BERT는 가려진 단어 맞히기(MLM), GPT는 다음 단어 맞히기(NTP).
  2. 파인튜닝(Fine-tuning) — 그 위에 작은 분류층을 붙여 내 과제 데이터로 짧게 추가 학습한다.

덕분에 레이블 데이터가 수천 건뿐이어도 꽤 좋은 성능이 나온다. RNN 시대에는 매번 밑바닥부터 학습해야 했던 것과 결정적으로 다른 점이다.

6. 실습 A: Transformer 인코더 직접 만들기

원문과 같은 과제 — 트위터 20,000건을 6가지 감정으로 분류한다. 레이블은 0(sadness), 1(joy), 2(love), 3(anger), 4(fear), 5(surprise). 구조 이해가 목적이므로 사전학습 없이 밑바닥부터 만든다.

위치 인코딩 층

class PositionalEncoding(nn.Module):
    def __init__(self, d_model, max_len=512, dropout=0.1):
        super().__init__()
        self.dropout = nn.Dropout(dropout)
        pe = torch.zeros(max_len, d_model)
        position = torch.arange(0, max_len).unsqueeze(1).float()
        div_term = torch.exp(torch.arange(0, d_model, 2).float()
                             * (-math.log(10000.0) / d_model))
        pe[:, 0::2] = torch.sin(position * div_term)
        pe[:, 1::2] = torch.cos(position * div_term)
        self.register_buffer("pe", pe.unsqueeze(0))   # [1, max_len, d_model]

    def forward(self, x):                # x: [B, L, D]
        return self.dropout(x + self.pe[:, :x.size(1)])

register_buffer로 등록하면 학습 대상은 아니지만 모델과 함께 GPU로 옮겨지고 저장된다.

분류 모델

class TransformerClassifier(nn.Module):
    def __init__(self, vocab_size, d_model=128, nhead=4, num_layers=2,
                 dim_ff=256, output_size=6, max_len=20, dropout=0.1):
        super().__init__()
        self.d_model = d_model
        self.embedding = nn.Embedding(vocab_size, d_model, padding_idx=0)
        self.pos = PositionalEncoding(d_model, max_len, dropout)
        layer = nn.TransformerEncoderLayer(
            d_model=d_model, nhead=nhead, dim_feedforward=dim_ff,
            dropout=dropout, activation="gelu",
            batch_first=True, norm_first=True)
        self.encoder = nn.TransformerEncoder(layer, num_layers=num_layers)
        self.dropout = nn.Dropout(dropout)
        self.fc = nn.Linear(d_model, output_size)

    def forward(self, x):                             # x: [B, L] 정수 인덱스
        pad_mask = (x == 0)                           # True인 자리가 PAD
        h = self.embedding(x) * math.sqrt(self.d_model)
        h = self.pos(h)                               # [B, L, D]
        h = self.encoder(h, src_key_padding_mask=pad_mask)
        h = h.masked_fill(pad_mask.unsqueeze(-1), 0.0)          # PAD 자리 0으로
        pooled = h.sum(1) / (~pad_mask).sum(1, keepdim=True).clamp(min=1)
        return self.fc(self.dropout(pooled))          # [B, 6]

코드에서 짚을 점

  • padding_idx=0 — PAD 토큰의 임베딩을 0으로 고정하고 학습에서 제외한다.
  • * math.sqrt(d_model) — 임베딩 크기를 위치 인코딩과 비슷한 스케일로 맞추는 원논문의 관행.
  • src_key_padding_mask — 이걸 빼먹으면 모델이 빈칸까지 의미로 읽는다. Transformer 구현에서 가장 흔한 버그다.
  • 마스크 평균 풀링 — 실제 토큰 자리의 벡터만 평균 낸다. 대안으로 문장 앞에 [CLS]를 붙이고 그 위치 벡터(h[:, 0])만 쓰는 방법도 있다. LSTM의 hidden[-1]에 해당하는 자리다.
  • norm_first=True — Pre-LN. 작은 모델에서도 학습이 훨씬 안정적이다.
데이터가 흘러가는 모양 (batch=32, seq_len=20, d_model=128)
단계설명출력 크기
입력정수 인덱스 시퀀스[32, 20]
임베딩 + 위치토큰 의미 + 순서 정보[32, 20, 128]
인코더 블록 ×2어텐션으로 문맥 반영 (모양 유지)[32, 20, 128]
마스크 평균 풀링문장 하나당 벡터 하나로 압축[32, 128]
출력층감정 6범주 점수[32, 6]

Transformer 학습의 3대 관례

AdamW(가중치 감쇠를 분리한 Adam), 워밍업(초반 학습률을 서서히 올림), 그래디언트 클리핑(clip_grad_norm_(model.parameters(), 1.0)). 셋 다 없어도 돌아가지만, 있으면 학습 안정성이 눈에 띄게 달라진다. 특히 워밍업 없이 높은 학습률로 시작하면 초반에 발산하는 일이 잦다.

예상 성능

사전학습 없이 20,000건으로 학습하면 정확도 0.88~0.91 수준으로, 같은 조건의 LSTM과 큰 차이가 나지 않는다. 데이터가 작으면 Transformer의 구조적 이점이 충분히 드러나지 않기 때문이다. 진짜 차이는 다음 절에서 나온다.

클래스별로 보면 데이터가 많은 sadness·joy는 f1 0.92 안팎, 데이터가 147건뿐인 surprise는 0.75 내외에 머문다. 이건 구조의 문제가 아니라 범주 불균형의 문제다. CrossEntropyLoss(weight=...)로 클래스 가중치를 주거나 소수 클래스를 오버샘플링하면 개선된다.

7. 실습 B: 사전학습 모델 파인튜닝

실무에서 이 과제를 받으면 실제로 쓰게 될 방법이다. 코드는 오히려 더 짧다.

from transformers import AutoTokenizer, AutoModelForSequenceClassification
from torch.utils.data import DataLoader

model_name = "distilbert-base-uncased"       # 한국어라면 "klue/roberta-base"
tokenizer  = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForSequenceClassification.from_pretrained(
            model_name, num_labels=6).to(device)

enc = tokenizer(list(data["text"]),          # 원문 그대로! 전처리 불필요
                truncation=True, padding="max_length",
                max_length=64, return_tensors="pt")

dataset = TensorDataset(enc["input_ids"], enc["attention_mask"],
                        torch.tensor(data["label"].values))
optimizer = torch.optim.AdamW(model.parameters(), lr=2e-5)   # 파인튜닝은 작은 lr

for epoch in range(3):                        # 2~4 에포크면 충분하다
    model.train()
    for input_ids, attn_mask, labels in train_loader:
        out = model(input_ids=input_ids.to(device),
                    attention_mask=attn_mask.to(device),
                    labels=labels.to(device))
        out.loss.backward()
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        optimizer.step(); optimizer.zero_grad()

달라지는 점

  • 전처리가 사라진다 — 토큰화, Vocab 생성, 정수 변환, 패딩을 토크나이저가 한 줄로 처리한다. 불용어 제거와 소문자 변환도 하지 않는다.
  • 학습률이 10배 이상 작다 — 밑바닥 학습은 3e-4, 파인튜닝은 2e-5~5e-5. 이미 좋은 가중치를 망가뜨리지 않기 위해서다.
  • 에포크가 짧다 — 3 에포크를 넘기면 대개 과적합된다.
  • 성능 — 같은 데이터에서 정확도 0.93 내외까지 올라가고, 데이터가 적은 surprise 같은 범주에서 격차가 가장 크게 벌어진다. 언어 지식을 이미 갖고 시작하기 때문이다.
그 다음 단계

모델이 더 커지면 전체 파라미터를 갱신하는 대신 LoRA 같은 경량 파인튜닝(PEFT)으로 일부만 학습한다. 레이블 데이터가 아예 없다면 LLM에 프롬프트만 주는 제로샷·퓨샷 분류도 선택지다. 다만 수만 건 규모의 고정된 분류 과제라면, 작은 모델을 파인튜닝하는 쪽이 비용과 지연시간 면에서 여전히 유리하다.

8. 한 장 요약과 점검 목록

흐름 한 줄로

텍스트 → 서브워드 토큰화(쪼개기+번호표) → 패딩과 어텐션 마스크 → 임베딩 + 위치 인코딩 → 셀프 어텐션 블록 ×N(문맥 반영) → 풀링(문장 벡터 하나로) → 출력층(감정 예측)

스스로 점검하기

  • Transformer가 RNN을 대체한 이유를 병렬성과 거리 두 축으로 설명할 수 있다.
  • 서브워드 토큰화가 OOV와 사전 폭발을 어떻게 동시에 해결하는지 예시로 말할 수 있다.
  • Attention(Q,K,V) 수식의 네 단계를 순서대로 짚을 수 있다.
  • √d_k로 나누는 이유를 softmax와 기울기로 설명할 수 있다.
  • 멀티 헤드가 연산량을 늘리지 않고 관점만 늘리는 구조임을 설명할 수 있다.
  • 위치 인코딩이 왜 필요한지, 없으면 무엇이 무너지는지 말할 수 있다.
  • 패딩 마스크를 빠뜨렸을 때 생기는 문제를 설명할 수 있다.
  • 인코더 전용·디코더 전용·인코더-디코더의 용도를 구분할 수 있다.
  • 파인튜닝의 학습률이 밑바닥 학습보다 작아야 하는 이유를 말할 수 있다.
  • surprise 범주의 성능이 낮은 원인을 데이터와 연결해 설명할 수 있다.
